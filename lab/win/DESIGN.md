## W1. Paths and names: `LAB.win` (new file `js/win.js`, owner MISSIONS, loaded right after `seed.js`)

```js
LAB.win = {
  HOST: 'AN-LAPTOP', USER: 'an', LABEL: 'an 的筆電',
  toWin(p)            // '/Users/an/Desktop/Project' -> 'C:\\Users\\an\\Desktop\\Project'; '/' -> 'C:\\'; '/Users' -> 'C:\\Users'
  fromWin(s, cwd)     // a Windows-ish path typed by a student -> canonical internal path or null.
                      // Accepts C:\…, c:/…, \… (drive root), ~ and ~\… and ~/…, .\ ..\ . .., forward or back slashes, mixed,
                      // trailing slash, quotes already stripped, and is CASE-INSENSITIVE (matches the real child's spelling).
  displayName(p)      // what File Explorer shows for a folder: Desktop→桌面, Documents→文件, Downloads→下載, Music→音樂,
                      // Pictures→圖片, Videos→影片, Favorites→我的最愛, Links→連結, 'Saved Games'→儲存的遊戲, Searches→搜尋,
                      // Contacts→連絡人, Users→使用者, '/'→'本機磁碟 (C:)'; anything else -> its real name (win-facts §9)
  promptPath(cwd)     // 'C:\\Users\\an' etc. for the PowerShell prompt
  fmtDate(ms)         // '2026/10/2  上午 09:47' (two spaces, no zero padding of month/day, 12-hour 上午/下午 hh:mm) (win-facts §4.2)
  fmtClock(ms)        // ['上午 09:52', '2026/10/2'] for the taskbar clock
}
```
Every app that shows or reads a path uses `LAB.win`; nobody re-implements the mapping. Missions and events keep internal paths.
