WEEK 05

讓 Codex 做對：驗證與 context window

這週先看怎麼寫一份驗證清單，讓 Codex 知道怎樣才算做好、做完自己檢查。Codex 可以在對話中途換模型，但每個模型都有自己的 context window。再看換模型時發生什麼事、用量為什麼會一次跳高，以及開工前怎麼選、真的要換時怎麼換。

影片 01怎樣才算做好：寫一份驗證清單

  1. 「做好了」是 Codex 自己判斷的，沒寫清楚的地方，每次可能不一樣。小安只說「幫我把銀杏散步地圖全部做好」：問兩次，一次做了 12 個景點、有檢查手機，另一次只有 4 個景點、沒檢查手機，手機上還要左右捲動（示意）。AI 每次的回答不一定一樣；它不知道你心裡的「做好」長什麼樣，所以「怎樣算做好」要寫下來。

  2. AGENTS.md 是長期協作規則，VERIFY.md 是驗收單。長期協作規則寫「怎麼做」：繁中、檔案放哪、不要改什麼，Codex 每段對話一開始都會讀它，這是 Week 3 學過的。驗收單寫「怎樣算做好、怎麼檢查」。VERIFY.md 這個檔名是我們的習慣，不是官方規定；OpenAI 的〈Codex Best practices〉建議把「做好是什麼、怎麼驗證」寫給 Codex。

  3. 好的驗證是「可以檢查」的。每一條都寫清楚：看什麼、怎麼看、應該看到什麼。「要好看」「不要有錯」都不算，有數字就寫數字。像「地圖上有 12 個標記」「寬 390 px 時不會左右捲動」，寫進清單就不用每次靠它猜；「標記點得到」沒有數字，就沒辦法檢查，改成「寬 390 px 時，每個標記至少 44 px」才檢查得了。

  4. 在 AGENTS.md 加上一定要寫的一句：「每次做完一個新功能，都要把 VERIFY.md 完整驗證一次，確保全部通過。」Codex 每段對話一開始會讀 AGENTS.md，但不會自己去找 VERIFY.md，要在 AGENTS.md 指名，它才會去讀。清單讓它比較可能自己發現問題，例如照片檔名的大小寫不一樣（Mac 不分檔名大小寫，網站會分），但不保證找得到所有問題。

  5. 你還是要抽查，清單會越寫越好。看它最後的回報表，自己點開一兩條確認；沒辦法檢查的，它應該照實說。發現新的問題，就加一條進驗收單。影片裡開頭兩次的結果、對話順序、展開的指令輸出和內建瀏覽器畫面是示意，check_data.py 的輸出是真的跑出來的。

影片 02不要一直換模型

  1. 每個模型都有自己的 context window。用 GPT-6 Luna 做了一陣子，讀過的對話都裝在 Luna 自己的 context window 裡，對話越長，裝得越滿。

  2. 中途換模型，新模型要從頭讀一遍。換成 GPT-6.1 Sol 之後，Sol 要把整段對話放進它自己的 context window，所以換過去的那一輪，用量一次跳很高。

  3. 換模型會讓快取失效。Codex 平常用快取（prompt caching）便宜地重用前面讀過的內容；OpenAI 官方文章〈Unrolling the Codex agent loop〉說明，中途換模型，快取會失效，整段要重新讀。

  4. 開工前就選好模型。選好之後，這段對話就一路用它。真的要換，先在原本的對話裡請目前的模型寫一段交接摘要，再開新對話、換模型、貼上摘要；也可以寫進 Week 3 學過的 AGENTS.md、progress.md。

  5. 影片裡的面板和數字都是示意。context window 面板借用 Claude Code 的 /context 畫面，Codex 看不到這張表；長條和用量也不是實測數字。

補充 1按下 Enter 之後，Codex 做了什麼

  1. 腦和手是分開的。模型在 OpenAI 的伺服器上，只會讀文字、寫文字；真正在你的電腦上跑指令、讀檔、寫檔的是 Codex app。Codex 透過 OpenAI 的 API，把對話送給模型。

  2. 按一次 Enter，背後來回很多次。Codex 把整段對話送給模型，模型回的要嘛是「請幫我跑這個指令」，要嘛是最後的回答。Codex 跑完把結果接到對話後面，再送一次，直到模型給出最後的回答（OpenAI〈Unrolling the Codex agent loop〉）。

  3. 讀過的內容會送到 OpenAI。模型看不到你的檔案，是 Codex 把檔案內容貼給它看。所以姓名、學號這類個資，先拿掉或換成代號，再放進專案資料夾。

  4. 搜尋在 OpenAI 那邊，下載在你的電腦。網路搜尋是 OpenAI 提供的工具，預設查的是 OpenAI 整理好的快取索引，不用你允許；查到的東西請它附上來源網址，自己點開確認。下載是 Codex 在你電腦上跑的終端機指令，預設的沙箱不能連網，所以要你允許，按之前先看清楚它要連去哪、下載什麼。

  5. 每一步的結果都疊進 context window。讀很大的檔案、搜很多次，對話就滿得很快。影片裡的面板、紙條張數和傳送次數都是示意；Windows 上指令名稱不一樣（PowerShell），流程一樣。

補充 2對話滿了會怎樣

  1. 快滿的時候，Codex 會自動壓縮。它把前面的對話換成一份比較短的精簡版，再接著做，你不用按什麼。依 Codex 原始碼，壓縮後留下的是這段對話的固定說明、你最近說的話和一份摘要；Codex app 的活動紀錄會多一列「Context automatically compacted」。

  2. 壓縮可能會掉細節。精簡版留的是重點，前面講過的細節，例如為什麼這樣決定、確切的欄位名稱、某次算出來的數字，可能就不在了，模型會開始「記錯」。影片裡缺考的人被算成 0 分是示意，壓縮不是每次都會掉同一件事。

  3. 官方的提醒。Codex 原始碼裡寫著：長對話和多次壓縮，可能讓模型比較不準；可以的話開新對話，讓每段對話小而專一。這句提醒在 Codex app 裡不會顯示。

  4. 習慣一：一件事，一段對話。一個分析問題、一張圖、一個錯誤、報告的一節，做完就開新對話。想看用了多少，可以在 Codex app 的設定 › General 打開 Show context window usage，輸入框底下會出現一個小圓環。

  5. 習慣二：要一直遵守的事，寫進檔案。寫進 AGENTS.md 或 progress.md。檔案存在你的電腦上，壓縮只動對話、不動檔案，開新對話時 Codex 會讀 AGENTS.md。影片裡的面板、紙條張數和數字都是示意。
