給用了 Codex 卻找不到檔案的你

Codex 做好的檔案，到底在哪裡？

答案只有一句：在你打開 Codex 的那個資料夾裡。

Codex、Claude Code 這類 AI Agent 都以「一個資料夾」為工作單位。搞懂這件事，你就知道它讀了什麼、改了什麼、東西放在哪。

  • 「Codex 說做好了，可是我在桌面找不到。」第 5 章
  • 「我叫它整理資料，它到底動了哪些檔案？」第 4 章
  • 「VS Code、終端機、Codex，看的是同一個東西嗎？」第 3 章

第 1 章

每個檔案都有一個地址

在談 AI 之前，先學會看「路徑」。

平常我們用檔案總管點來點去：桌面、下載、文件。這些是給人看的暱稱。電腦自己記的，是檔案的完整地址，叫做路徑（path）。

例如小安的問卷資料，完整路徑是：

C:\Users\an\Desktop\Project\data\問卷_A班.csv

從左邊讀到右邊：C 槽 → Users → an（小安的帳號）→ Desktop（就是檔案總管裡的「桌面」）→ Project → data → 問卷_A班.csv。每一段都是一層資料夾，最後一段才是檔案。

Mac 的道理一樣，只是改用斜線 / 分隔，也沒有 C 槽：/Users/an/Desktop/Project/data/問卷_A班.csv

為什麼要先學路徑？

Codex 回報「已存到 output/report.md」時，它給你的就是地址的一部分。看得懂地址，就找得到檔案。

第 2 章

Agent 只在一個資料夾裡工作

你在哪個資料夾打開 Codex，那裡就是它的工作室。

想像你請了一位助理。你不會把整間房子的鑰匙交給他，而是帶他到一間工作室：「這次的作業都在這裡，資料在 data，做好的東西放 output。」

AI Agent 也是這樣。Codex、Claude Code 這類工具啟動時，都會綁定一個資料夾，叫做工作資料夾（working folder，也常叫 workspace 或專案資料夾）。它讀檔、寫檔、執行指令，都從這個資料夾開始。

Agent 的「工作範圍」不是整台電腦，
而是你交給它的那一個資料夾。

為什麼用「資料夾」當單位？

這不是 Codex 的怪規定。以資料夾為單位，同時解決了六個問題：

01劃出範圍

Codex 看不到你腦中的想法。資料夾告訴它：「這次作業相關的東西都在這裡。」它會從這裡開始列檔案、搜尋、讀內容，不會去翻你的其他課程。

02保護其他檔案

預設的 Auto 模式下，Codex 在資料夾裡面可以直接讀檔、改檔、執行指令；要修改外面的檔案或上網，會先停下來問你。照片和其他作業就不會被誤動。

03路徑的起點

Codex 說「存到 output/report.md」，意思是「工作資料夾裡的 output/report.md」。起點不同，檔案的落點就不同。第 5 章會實際操作。

04規則放在這裡

資料夾最上層的 AGENTS.md 會被 Codex 自動讀取，就像貼在工作室牆上的規則：用什麼語言寫、檔案放哪裡、哪些東西不能動。

05可以反悔

一個資料夾可以用 Git 記錄每一次變更。Codex 改錯了，輸入 /diff 就能看它改了什麼，再退回原本的版本。

06大家都認得

VS Code、終端機、檔案總管、Codex 都能「打開一個資料夾」。大家以資料夾為單位，看到的就是同一批檔案。這是下一章的主題。

「要信任這個資料夾嗎？」

第一次在新的資料夾啟動 Codex，它會問你要不要信任這個資料夾。意思其實是：「要把這間工作室的鑰匙交給我嗎？」先看清楚路徑是不是你的作業資料夾，再同意。如果畫面上出現的是 C:\Users\an 或 C:\Users\an\Desktop（桌面本身，還沒進到 Project），先離開，換到正確的資料夾再開。

第 3 章

四扇門，同一個房間

Codex、VS Code、終端機、檔案總管，看的是同一個資料夾。

很多人以為 Codex 做好的檔案存在「聊天室裡」，要另外下載。其實 Codex 只是一扇門，門後是硬碟上真正的資料夾。VS Code 是另一扇門，終端機、檔案總管也是。

從哪一扇門進去改東西都一樣，其他門看到的會一起改變，因為房間只有一個。按下面的按鈕試試看。

四扇門各自怎麼打開同一個資料夾

工具用來做什麼怎麼對準專案資料夾
檔案總管／Finder用眼睛看、拖拉、打開檔案一層一層點進 桌面\Project
VS Code檢視和編輯檔案內容「檔案 → 開啟資料夾」，選 Project；或在終端機輸入 code .
終端機打文字指令操作檔案cd 到資料夾。VS Code 內建的終端機（Ctrl + `）會自動停在開啟的資料夾
Codex CLI會自己讀、寫、執行的 AI 助理先 cd 到資料夾再輸入 codex，或 codex --cd 路徑
Codex App／VS Code 擴充同上，有圖形介面App：新增專案時選這個資料夾。VS Code 擴充：用的就是 VS Code 目前開啟的資料夾

最不容易迷路的開法

用 VS Code 開啟專案資料夾 → 按 Ctrl + ` 打開終端機 → 輸入 codex。這樣編輯器、終端機、Codex 三個都對準同一個地方。

第 4 章

你叫 Codex 做事時，它實際在做什麼

看起來像聊天，其實它在資料夾裡反覆做三件事：讀、跑、寫。

你打一段話，Codex 會把它拆成一連串小動作。每個動作都很具體，也都留得下痕跡：

  • 讀取打開檔案看內容，例如 AGENTS.md 和你的資料。
  • 執行指令在終端機裡跑指令，例如列出檔案、執行程式。起點永遠是工作資料夾。
  • 寫入新增或修改檔案。寫完的檔案立刻出現在硬碟上。

下面是小安請 Codex 整理問卷的完整過程，按「下一步」或「播放」一步一步看。

看懂 Codex 畫面上的動詞

Codex 的畫面會出現類似 Read、Ran、Edited、Added 的字眼，後面接的是檔案名稱或指令。那就是它剛剛讀過、執行過、改過的地方。看不懂的時候，直接問它：「你剛剛改了哪些檔案？」

第 5 章

同一句話，檔案卻跑到不同地方

「存到 output/chart.png」是從工作資料夾出發的短地址。

第 1 章那種從 C: 一路寫到底的地址，叫絕對路徑。Codex 和程式平常更常用短的寫法，例如 output/chart.png，叫做相對路徑：從工作資料夾出發，往下找 output，再找 chart.png。

所以同一句話，Codex 開在不同資料夾，檔案就落在不同地方。這就是「Codex 說存好了，我卻找不到」最常見的原因。

第 6 章

迷路急救包

找不到 Codex 做的檔案時，照順序做這五步。

  1. 確認 Codex 開在哪裡

    Codex CLI 啟動畫面上 directory: 那一行，就是它的工作資料夾。也可以在 Codex 裡輸入 /status 查看。用 App 的話，看目前所在的專案是哪一個。

  2. 直接問它要完整路徑

    對 Codex 說：

    請列出你剛剛新增或修改的所有檔案，每一個都給我完整路徑。

  3. 用終端機確認位置，並在檔案總管打開

    想做的事Windows（PowerShell）Mac（終端機）
    我現在在哪個資料夾？pwdpwd
    這裡有哪些檔案？dirls
    在檔案總管／Finder 打開這裡explorer .open .
    用 VS Code 打開這裡code .code .
    進入某個資料夾cd 資料夾路徑cd 資料夾路徑

    指令裡的 . 代表「目前這個資料夾」。

  4. 從 VS Code 反查檔案位置

    在 VS Code 左側的檔案上按右鍵，選「在檔案總管中顯示」（Mac 是「在 Finder 中顯示」），或選「複製路徑」拿到完整地址。

  5. 看它改了什麼

    在 Codex CLI 輸入 /diff，會列出這個資料夾裡被改過和新增的內容（資料夾要先用 Git 管理）。Codex App 也有檢視變更的面板。

Windows 使用者特別注意 OneDrive

很多電腦開了 OneDrive 備份，「桌面」和「文件」其實在 C:\Users\an\OneDrive\Desktop 這類位置，而不是 C:\Users\an\Desktop。檔案總管看起來一模一樣，路徑卻不同。找不到檔案時，用 pwd 看真正的地址。

第 7 章

好習慣：一個作業，一個資料夾

資料夾整理好，Codex 和你都不會迷路。

  • 每個作業開一個自己的資料夾，只在這個資料夾裡啟動 Codex。
  • 不要直接在桌面、下載或整個家目錄啟動 Codex，要先進到專案資料夾（例如桌面上的 Project）。範圍太大，容易讀錯、寫錯。
  • 原始資料放 data/，產出放 output/，規則寫在 AGENTS.md。
  • 下載的檔案先搬進專案的 data/，再叫 Codex 處理。
  • 讓 Codex 大改之前先留一份備份，會用 Git 更好。
  • 資料夾名稱盡量用英文、數字、底線（例如 Project、stats_final）。中文可以用，但少數舊程式遇到中文或空格會出錯。
建議的資料夾樣子
AGENTS.md 範例 
# 專案規則
- 這是「教育統計」期末作業，請用繁體中文。
- 原始資料在 data/，不要修改原始資料。
- 產生的報告、圖表都放在 output/。
- 不要讀取或修改這個資料夾以外的檔案。
- 做完後，列出你新增或修改的檔案完整路徑。
