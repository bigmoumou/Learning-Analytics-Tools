# 維護說明

這份文件給維護網站的人：資料夾結構、新增影片、影片與 HLS 的規則、多語系、版權與授權、本機預覽。專案介紹、授權摘要和參與方式見 [README](../README.md)。

網站：https://learning-analytics-tools.pages.dev/

網站放在 Cloudflare Pages，push 到 `main` 就會自動部署。GitHub Pages 在台灣只有約 50 KB/s，影片會卡，所以不再用它當網址；它仍然開著，只負責把舊網址 https://bigmoumou.github.io/Learning-Analytics-Tools/ 轉到 Cloudflare 上的同一頁（每一頁 `<head>` 最前面的轉址程式，加上 `404.html`；`tools/template/week.html.tmpl` 也有同一段）。

每週（Week 3 – Week 16）只有一頁：標題，接著每支影片一段（影片、章節、幾則重點），不再往下分頁。一週通常有兩支以上的影片。網站有四種語言：繁中（預設）、简中、English、Tiếng Việt（見下面「多語系」）。

## 新增一支影片

以下指令都在 repo 資料夾執行（`tools/` 裡的 `.sh` 是 bash 腳本，Windows 用 Git Bash）。例子用還沒開放的 Week 5；已經有頁面的週次（例如 Week 4）加第二支影片時，slug 的數字要接著編（`02-…`）。

```bash
tools/new-video.sh 5 01-relative-path "相對路徑的起點"
```

1. 上面這行會建立 `製作/week05/01-relative-path/`、`weeks/week05/video/01-relative-path/`，這週還沒有頁面時從範本建立 `weeks/week05/index.html`，並在頁面上加一段這支影片。slug 用「兩位數字-英文小寫」：數字是這週的第幾支，英文描述主題。
2. 在 `製作/week05/01-relative-path/` 做影片，成品放在 `out/final.mp4`。
3. 放上網站：

   ```bash
   tools/publish-video.sh "../製作/week05/01-relative-path/out/final.mp4" weeks/week05/video/01-relative-path 12
   ```

   最後的 `12` 是封面取第幾秒的畫面（可省略：已有封面時不動，沒有時取 30% 的位置）。影片會重新壓縮（H.264 CRF 23），每 8 秒一個關鍵影格，切成 8 秒一段的 HLS。
4. 補完週次頁裡「待填」的地方：標題、說明、章節時間（`data-t` 是秒數；程式裡的 class 是 `chapters`，頁面的 aria-label 稱為「影片片段」）、重點，以及每一處的簡中、英文、越南文翻譯（`data-zh-hans`、`data-en`、`data-vi`）。重點寫短句就好，不要加小標題。
5. 這週第一次開放時，在 `assets/course.js` 的 `WEEKS` 加上這一週（`i18n` 三種語言都要有）：

   ```js
   5: {
     status: "ready",
     title: "這週的標題",
     summary: "一兩句話的摘要",
     href: "weeks/week05/",
     thumb: "weeks/week05/video/01-relative-path/thumb.jpg",   // 清單用的小圖（800×450）
     still: "weeks/week05/video/01-relative-path/poster.jpg",  // 膠捲畫格用的大圖（1920×1080）
     meta: "2 支影片・共 3 分鐘",                                // 首頁顯示的一行說明
     i18n: {
       "zh-Hans": { title: "…", summary: "…", meta: "2 个视频・共 3 分钟" },
       en: { title: "…", summary: "…", meta: "2 videos · 3 min" },
       vi: { title: "…", summary: "…", meta: "2 video · 3 phút" },
     },
   },
   ```

   首頁膠捲會自動把這一格從「準備中」換成影片封面，開場也會停在最新開放的一週。
6. 更新 `README.md` 的「AI 教學影片」，繁中和 English 兩處都要改：影片表格加一列（縮圖 `weeks/weekNN/video/NN-slug/thumb.jpg`、網站連結、長度、章節／重點數、內容），開頭那一句的日期、已公開的週次、支數、總長度、章節數和重點數也要改。這週第一次開放時，「開源與開放內容的範圍與規劃」表格裡「Week 5 到 Week 16」那一列也要改。`tools/check.mjs` 不檢查 README 和 `docs/`，改完在 GitHub 上看一次圖片和連結。
7. `node tools/check.mjs`，沒有錯誤再 commit、push 到 `main`（Cloudflare Pages 約 1 分鐘更新）。

## 補充教材

每週最後面可以放一到兩個補充教材（例如 Week 3 的「終端機介紹」）。做法和一般影片相同，差在下面幾點（`new-video.sh` 只會做一般影片的段落，補充教材的段落照下面手動加）：

- slug 用 `s1-…`、`s2-…`（例：`s1-terminal-mac`），影片放在 `weeks/weekNN/video/s1-…/`，一樣用 `publish-video.sh` 產生。
- 段落放在這週所有影片之後、`<nav class="pager">` 之前：`<section class="unit unit-supp" id="s1-…">`，標題前的標籤寫 `<span class="unit-num" data-ui="video.supp" data-n="1">補充 1</span>`。
- `assets/video.js` 看到 `unit-supp` 會在播放清單裡寫「補充 1」（四種語言跟著換），並在第一個補充教材前面加一行「補充教材」小標；手機橫排時不顯示小標。
- 要給學生下載的練習檔放在 `weeks/weekNN/files/`（例：`weeks/week03/files/week3.zip`），重點裡用相對連結 `files/week3.zip` 加 `download` 屬性。翻譯屬性裡的連結用單引號：`<a href='files/week3.zip' download>`。檔案一樣要小於 25 MiB。
- `assets/course.js` 的 `meta` 和 README 的影片表格也要算進補充教材。
- 清單上的標題、章節名稱裡的（…）、(…) 會被 `video.js` 包成不拆行的一段，換行時整組一起換，不會剩下孤零零的「（Windows）」；排在換行後行首的「（」也會把左邊多出來的半個字空白收掉（`.np`、`.np-fw`、`.ls`）。寫標題時照常用全形括號就好，不用另外處理。
- 手機（760 px 以下）的清單是橫排的：每一組前面有一小欄標示組名（補充教材、課堂練習），開頁或選到某一段時，清單會自動捲到那一格。

## 課堂練習（模擬 Mac）

`lab/mac/` 是一台在瀏覽器裡執行的模擬 Mac：純 HTML、CSS、JavaScript，沒有後端也不用建置。學生在上面操作 Finder、終端機、Codex 和 Code，照任務卡完成每週的練習；檔案、Codex 對話、終端機歷史和任務進度都只存在學生自己瀏覽器的 `localStorage`。目前有 Week 3 的 7 個任務；Windows 版規劃中（`lab/mac/DESIGN.md` 把檔案標成 `[PORTABLE]` 和 `[SKIN]`，換外觀時只重寫 `[SKIN]` 的部分）。

怎麼組織：

- `lab/mac/index.html` 是頁面骨架（假的 Mac 畫面佔滿整頁，任務卡是浮在左上角的液態玻璃卡片）；`css/` 是樣式；`js/` 全部掛在一個全域 `window.LAB` 底下，用普通的 `<script src>` 依序載入（不用 ES module，所以 `file://` 也能開）。載入順序見 `index.html`，每個檔案的職責見 `lab/mac/DESIGN.md` 的「File layout」。
- `lab/mac/DESIGN.md` 是規格，`lab/mac/README.md` 寫怎麼開和網址參數（`?reset=1` 清進度、`?welcome=0`、`?mission=<id>`、`?now=…`）。
- 練習頁自己有一套 CSS，不載入 `assets/week.css` 和 `assets/course.js`；只有繁中。它仍是網站的一頁，所以 `check.mjs` 的規定照樣適用：github.io 轉址、載入 `i18n-strings.js` 和 `i18n.js`、版權聲明、本機連結都找得到、每個檔案小於 25 MiB。圖示全是自己畫的 SVG，不放 Apple、Microsoft、OpenAI 的圖檔。桌布的署名在 `NOTICE.md`。

週次頁上的入口：

- Week 3 頁面最後一段是 `<section class="unit unit-lab" id="lab-mac" data-thumb="lab/thumb.jpg">`（在補充教材之後、`<nav class="pager">` 之前）。它不是影片，沒有 `<video>`：膠捲裡是一張筆電的圖（`weeks/week03/lab/poster.jpg`），點圖或「進入遠端電腦（Mac）」按鈕都在同一個分頁打開 `../../lab/mac/`；下面是簡介、一行提醒（畫面是繁中、用電腦操作）和幾則重點。所有文字照一般規定寫 `data-zh-hans`、`data-en`、`data-vi`，共用的幾個字串（`video.lab`、`reel.lab`、`lab.enter`）在 `assets/i18n-strings.js`。
- `assets/video.js` 把它當成播放清單的一格：`unit-lab` 在清單上寫「練習 N」，第一個 `unit-lab` 前面有「課堂練習」小標（和補充教材同一套分組，`video.js` 裡的 `GROUPS`）；縮圖取 `data-thumb`；沒有長度標籤、沒有觀看進度；某支影片播完後，「下一支」只接影片，不會自動打開課堂練習。`check.mjs` 也會檢查 `data-thumb` 指到的檔案。
- 要加 Windows 版：先做好 `lab/win/`，再在週次頁加一段 `<section class="unit unit-lab" id="lab-win" data-thumb="lab/thumb-win.jpg">`，編號寫 `data-n="2"`，圖用 Windows 筆電的版本。
- 筆電圖是原創繪圖（鋁合金外框、黑邊框、底座）加一張練習畫面的截圖，由 `製作/lab-mac/poster/make_poster.py` 產生：先在 repo 資料夾 `python -m http.server 8843`，再用 opus-video 環境執行該腳本，會寫出 `poster.jpg`（約 150 KB）和 `thumb.jpg`（約 35 KB）。練習畫面改版後重做一次，圖才不會和實際畫面差太多。筆電圖算教材內容（CC BY-NC-SA 4.0）。

新增某一週的任務：

1. 在 `lab/mac/js/` 新增 `missions-weekNN.js`，仿 `missions-week3.js`：呼叫 `LAB.missions.register({ id: 'w4-01-…', week: 4, order: 1, title, minutes, intro, prepare, steps: [{ id, text, hint, answer, check }], outro })`。每一步的 `check` 看事件或狀態自動判斷；`text`、`hint`、`answer` 的寫法（三層：目標、模式、完整答案）、事件清單和 `api` 見 `DESIGN.md` 的 §5.1、§3.3。所有學生會讀到的字都用繁體中文（台灣用語）。
2. 在 `index.html` 的 `<script src="js/missions-week3.js">` 後面、`boot.js` 之前加一行載入新檔案。
3. 任務需要的檔案放進 `js/seed.js`（起始檔案系統）；任務卡的清單目前只有 Week 3，多週並存時怎麼分組要先看 `js/missions.js` 和 `DESIGN.md` §6.1。
4. 週次頁的課堂練習段落、簡介和重點跟著改，`README.md` 的課堂練習說明也要更新。

測試：

- 測試放在 repo 外面的 `製作/lab-mac/tests/`（`lab_e2e.py` 是整體的端對端測試，另有針對修正的檢查）。用 Playwright（opus-video 環境）跑：先在 repo 資料夾 `python -m http.server 8810`，再執行 `bash ~/.claude/skills/opus-video/scripts/ov python "../製作/lab-mac/tests/lab_e2e.py"`，要全部通過才推。
- 改了 `lab/mac/` 之後也要跑 `node tools/check.mjs`。週次頁和播放清單的改動，用手機寬度（360、390 px）和桌機各看一次，確認沒有橫向捲動。

## 影片

- 網站只放 HLS，不放 mp4：Cloudflare Pages 不支援 Range 請求，mp4 放上去無法跳到指定時間；而且同一支影片存兩份，14 週下來會超過 GitHub Pages 1 GB 的上限。mp4 留在 `製作/` 裡。
- 每個檔案都要小於 25 MiB（Cloudflare Pages 的上限，超過時整個部署會失敗）。`publish-video.sh` 和 `check.mjs` 都會檢查。
- 週次頁先載入 `assets/vendor/hls.light.min.js`，再載入 `assets/video.js`（範本已經寫好）。
- 連結到影片的某個時間：`weeks/week03/#t=30` 是第一支影片的 30 秒，`weeks/week03/#02-agents-md-context&t=30` 是指定的那一支，`weeks/week03/#02-agents-md-context` 直接打開那一支。
- 一週有兩支以上影片時，`assets/video.js` 會自動把週次頁變成播放清單：一次只顯示一支（播放器、章節、重點），清單在右邊（手機在上方），從各個 `<section class="unit">` 自動產生，頁面不用另外寫。清單上緣的細線是觀看進度（記在學生自己的瀏覽器），影片播完會出現「下一支」；沒選到的影片等點了才下載。只有一支影片的週次維持原本的版面。
- 影片確定了再 commit：重新渲染過的舊版本會一直留在 git 歷史裡，讓 repo 越來越大。
- `publish-video.sh` 會自己找 ffmpeg（PATH，或 opus-video conda 環境裡的那一份）；要指定時用 `FFMPEG=...`。

## 多語系

繁中（預設）、简中、English、Tiếng Việt。右上角的語言選單由 `assets/i18n.js` 自動加上，選了會記住；網址加 `?lang=zh-Hans`、`?lang=en`、`?lang=vi` 可以直接指定（分享連結用）。第一次來的人一律是繁中（不看瀏覽器語言）。

- 繁中直接寫在 HTML 裡（沒有 JavaScript 也看得到），其他語言這樣標：
  - 全站共用的文字（頁尾、翻頁、首頁按鈕……）：`data-ui="key"`，屬性用 `data-ui-attr="aria-label:key"`，文字在 `assets/i18n-strings.js`。
  - 這一頁自己的內容（標題、章節、重點）：加 `data-i18n`，翻譯直接寫在 `data-zh-hans`、`data-en`、`data-vi`（可以含 `<strong>`、`<code>`；引號用「“ ”」，不要用 `"`）。屬性（例如 meta description）用 `data-i18n-attr="content"`。
  - 首頁和翻頁用的週次標題、摘要、meta：`assets/course.js` 的 `WEEKS[n].i18n`。
- 每一頁的 `<head>` 要先載入 `i18n-strings.js`、`i18n.js`（不要 defer），範本已經寫好。
- 簡中會自動改用 Noto Sans SC 字型（選到時才載入）。
- 影片畫面裡的字是繁中；非繁中時，週次頁標題下會有一行說明（`video.note`）。
- `tools/check.mjs` 會檢查：每個 `data-i18n` 元素三種翻譯都有、`data-ui` 的 key 都存在、四種語言的介面文字一樣齊、已開放的週次在 `WEEKS` 裡有三種語言。

## 作品集

首頁、週次頁上方的「作品集」按鈕連到 `works/`：先選練習，再點縮圖，在網站裡打開學生的網頁（上方一條細列：回到列表、上一位／下一位、在新分頁開啟；方向鍵也能換人，Esc 回到列表）。學生的網頁放在 iframe 裡，和網站的樣式、程式互不干擾。

只收錄學生同意公開的作品（同意公開也包括放在這個公開的 GitHub repo）；學生要求撤下時，從 `works/<分類>/` 刪掉那個資料夾和縮圖，`assets/works-data.js` 刪掉那一筆；如果 `_redirects` 裡有轉到這個代號的規則，也一起刪掉（不然 `check.mjs` 會報轉址目的地不存在）。

學生的作品是純靜態網頁（html、css、js）。收到一批之後：

1. 放在 repo 外面，例如 `製作/works/hw1/收到的作品/`，每位學生一個資料夾或一個 .zip，名稱以學號開頭（`41000000A`、`41000000A_姓名.zip` 都可以；這裡的學號是假的範例）。
2. 匯入（第一次匯入一個新的練習要加 `--title`，`--week` 可省略）：

   ```bash
   node tools/add-works.mjs hw1 "../製作/works/hw1/收到的作品" --title "HW1" --week 4
   ```

   - 學號只留前 2 碼和後 3 碼（`41••••00A`），網址和資料夾用 `41xxxx00a`；遮完和別人一樣時，一次多露出一碼，直到分得開。學號和代號的對照表存在 `製作/works/<分類>/ids.json`，**不放進 repo**（GitHub 上的 repo 是公開的）。同一位學生重新匯入，代號不變。
   - 會列出要處理的地方：25 MiB 以上的檔案（不匯入）、寫死的本機路徑、找不到的檔案（網站上大小寫要完全一樣）、檔案裡出現完整學號、用到的外部網站。檔案裡出現完整學號或姓名時，先請學生改掉或徵得同意，再上線。
   - 縮圖用 Edge 或 Chrome 的無頭模式截圖（找不到時用 `BROWSER=...` 指定），ffmpeg 轉成 640×400。
3. 新的練習要在 `assets/works-data.js` 補上簡中、英文、越南文的標題（`i18n`）。
4. 本機預覽看一遍（見下面），`node tools/check.mjs`，再 commit、push。

老師推薦（星等）：在 `assets/works-data.js` 某一筆作品加上 `"stars": 2`（1 到 3 的整數，手動加）。有星的作品排在最前面，星多的在前；同樣星數和沒有星的，照 `works-data.js` 裡的順序（匯入時照學號排）。作品列表、看作品時的上一位／下一位、作品集首頁那一列的縮圖，都用同一個順序（`assets/works.js` 的 `byStars()`）。畫面上在代號後面顯示琥珀色的 ★，不加框；螢幕閱讀器讀成「老師推薦 N 顆星」（`works.stars`，四種語言）。重新匯入同一位學生不會洗掉 `stars`；`check.mjs` 會提醒不是 1 到 3 整數的值。

改代號（例如遮蔽規則改了）：`git mv` 作品資料夾和縮圖到新代號；`assets/works-data.js` 那一筆改 `code`、`label`，並在 `"was"` 留下舊代號，網址 `?s=舊代號` 會自動換成新的；`_redirects` 加兩條 301（`/works/<分類>/舊代號/*` 轉 `/works/<分類>/新代號/:splat`，以及不帶斜線的 `/works/<分類>/舊代號`），舊的資料夾網址才不會失效；最後更新 repo 外的 `製作/works/<分類>/ids.json`。2026-10-03 學號改成露出後 3 碼時，HW1 就是這樣處理的。

學生的網頁不套用網站自己的規定（轉址程式、版權、多語系），`check.mjs` 只檢查檔案大小，找不到的檔案列成提醒；另外會檢查 `assets/works-data.js` 的每件作品都有資料夾和縮圖、代號是遮蔽過的。作品集頁面的頁尾用 `footer.works`（見下面「版權與授權」）。

## 本機預覽

在 repo 資料夾開一個本機伺服器，再用瀏覽器打開 http://localhost:8000/：

```bash
python -m http.server 8000
```

直接雙擊 `index.html` 也看得到，但瀏覽器的安全限制會讓首頁膠捲裡的影片封面圖和週次頁的影片顯示不出來。
